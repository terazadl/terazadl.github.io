## §1 Goals / Non-goals

### Goals

- 首屏（desktop + mobile）只突出一期 featured 周报；另一国为紧凑同步行，降低双卡密度。
- 保持卡片 4 层（meta / title / 一句 dek / 一个 CTA）；卡片无 bullets。
- 「最新写作」不与 featured 周报同篇重复。
- （可选 polish）菜单 overlay 打开时弱化/遮罩底层噪声。
- （选题轨）启动 2 个可复现系列槽；周报加可选回顾块；技术线有一条连续项目 IA 页。

### Non-goals（本轮不做）

- 全站重设计 / 换主题皮肤大改
- 品牌改名（不必；Lei Deng / 独立研究保持）
- 重写全部旧文
- RSS / 邮件订阅产品化（仍属后续；文档测试可探测现有 atom 入口，但不要求新 UI）
- Radar / Polymarket 观测站功能重建（仅允许首页/系列页 链接与 IA，不重建产品）
- 把选题轨 US-5..7 当作 UX 代码合入门禁（可并行，由责任编辑/作者交付）

## §2 Track UX（P0）— User Stories

### US-1 · Desktop 首屏：仅一张 featured 周报卡（P0）

作为 东亚政经读者，我希望 桌面首屏默认只看到 一张 完整周报卡，另一国是紧凑「同步推送」行，以便 一眼抓住「本期主菜」而不被双卡+对照+radar 淹没。

做法

- 1280px（及宽屏）默认：1 × featured 完整卡（编辑选中或日；当前建议默认中国，日本为辅，可配置）。
- 另一国：单行 compact sync row（文案模式对齐 mobile：JAPAN WEEKLY · 第N期 · 同步推送 · {短题} →）。
- 对照句（中日一句对照）与 Radar 缩略：不得抢 featured 卡主 CTA；优先下移至 fold 下，或视觉权重明显弱于 featured 卡。
- 禁止 桌面恢复「两张完整 4 层卡并排」作为默认首屏（除非显式「展开双卡」且默认折叠——本轮不要求做展开交互，默认一卡即可）。

AC

- AC-1.1 视口 1280×800，不滚动：可见 Hero（短）+「近期周报」区标签 + 至多一张完整 .weekly-brief-card。
- AC-1.2 同屏可见另一国 compact sync row（非整卡）；无第二张完整周报卡。
- AC-1.3 Featured 卡仍为 4 层；主 CTA tap/click 可达本期全文。
- AC-1.4 对照句 / Radar snapshot 不与两张完整周报卡同时挤在首屏（若保留，须在 featured 卡主视觉之后或 fold 下）。
- AC-1.5 与 2026-09-09 foundation 一致：mobile-first 原则；桌面收敛到与 mobile 同一信息架构（一主一辅），而非「桌面例外双完整卡」。

### US-2 · Mobile 保持现有改进；菜单 overlay 可选 polish（P0 保持 / P1 可选）

作为 手机读者，我希望 390px 继续是「中国完整卡 + 日本同步行」，且打开菜单时不被底层嘈杂内容干扰。

做法

- 保持 现网 mobile 一主一辅（回归锁定）。
- 可选：.research-mobile-nav 打开时，对底层主内容加遮罩 / inert / 降低可见噪声，避免「菜单字 + 周报字」叠读。

AC

- AC-2.1 视口 390×844：不滚动可见 Hero + section + 一张完整周报卡；第二国为「同步推送」行（或等价 compact）。
- AC-2.2 无挤并排双完整卡；无卡片 bullets。
- AC-2.3 主 CTA tap target ≥ 44×44 CSS px。
- AC-2.4 （可选）菜单 aria-expanded=true 时，底层周报区被遮罩或不可点；关闭后恢复。失败不挡 P0 合入。

### US-3 · 「最新写作」不重复 featured 周报（P0）

作为 扫描首页的读者，我希望「最新写作」列出生活/项目/其他文章，而不是再看见刚在首屏点过的同一期中/日周报。

做法

- 静态构建列表与前端 contentIndex 过滤：排除当前 featured（及 sync 行指向）的周报 permalink。
- 「最新写作」优先生活 / 项目 / 非周报政经长文。

AC

- AC-3.1 首页「最新写作」列表中，不出现当前 featured 中国周报同篇 URL。
- AC-3.2 不出现当前 sync 行日本周报同篇 URL（若 sync 指向当期日刊）。
- AC-3.3 列表仍至少展示 ≥1 条非周报内容（有库存时）；空态需明确，不得用周报填坑冒充「最新」。

### US-4 · 卡片锁定 4 层；禁止 bullets 回潮（P0）

作为 读者，我希望 周报卡始终是 meta / title / 一句 dek / 一个 CTA，不要再在卡上看到 3 条要点抢注意力。

做法

- 首页卡渲染字段：只用首页导语（dek）；要点仅正文。
- CSS/模板删除任何 .weekly-brief-bullets / 等价列表绑到卡上的路径。

AC

- AC-4.1 Featured 卡 DOM：无 ul/ol 要点列表（或视觉等价 bullets）。
- AC-4.2 仅一层 dek（约 ≤60 汉字为宜）；一个主 CTA（如「阅读全文」）。
- AC-4.3 回归：390px 与 1280px 均满足。

## §3 Track Editorial / 选题（P1）— User Stories

可为 内容运营 交付，不强制同一代码 PR。负责人：责任编辑 / 作者；agent 可协助建栏目页骨架与 front matter，但不以代码完成代替选题质量。

### US-5 · 新增连续系列槽（先定 2 个）（P1）

作为 回访读者，我希望 除中日周报外，有可预期的连续系列，以便 形成「主菜 + 配菜」阅读习惯。

启动 2 系列（本轮必选定义；至少各发 1 篇样例或栏目页占位）

- 中日生活成本对照（房租/菜篮/通勤/社保体感等可复用模板）
- 招商承诺 → 落地（跟踪地方招商报道 vs 后续落地/就业/财政线索；可衔接遂宁/雅安等已有线索）

候补池（选题增强，不挡 US-5 关闭）：AI 就业、县域/地方财政、周报命中率栏目。

AC

- AC-5.1 站内可发现 2 个系列入口（栏目页或 topics 下稳定 URL）。
- AC-5.2 每个系列有一句话定位 + 更新节奏说明（如「双周 / 不定期」）。
- AC-5.3 首页或主题总览有链到系列（IA 可见，非仅作者脑内）。

### US-6 · 周报模板增加可选「上周判断回顾/修正」（P1）

作为 认真读者，我希望 周报偶尔回顾上周判断是否打脸/需修正，以便 建立可信度与「命中率」叙事。

做法

- 正文模板增加可选块：## 上周判断回顾（或等价）；无内容时可整块省略。
- 不要求每期必有；有则放正文靠前，不进首页卡。

AC

- AC-6.1 周报写作模板/文档中写明该可选块及字数建议。
- AC-6.2 至少 1 期样例文使用该块（中或日均可）。
- AC-6.3 首页卡仍无该块摘要 bullets。

### US-7 · 技术线连续项目系列页（IA 链接）（P1）

作为 技术好奇读者，我希望 有一个项目系列页把 Polymarket Observatory 与后续工具串起来，以便 理解「政经站也有可跟的工程线」。

做法

- 新建或强化 /projects/ 下系列索引页：链到 Observatory +「未来工具」占位说明。
- 不做 观测站功能重建；仅 IA / 文案 / 链接。

AC

- AC-7.1 存在稳定系列 URL，列出 Observatory 入口。
- AC-7.2 首页或「项目」导航 2 跳内可达该系列页。
- AC-7.3 文案区分「观察工具」与政经判断，避免概率=结论。

## §4 Acceptance · 首屏规则（UX 门禁）

### 390px（mobile）

| 规则 | 要求 |
| --- | --- |
| 不滚动可见 | Hero（名 + 一行 tagline）+「近期周报」标签 + ≤1 张完整周报卡 |
| 第二国 | compact「同步推送」行（非整卡） |
| 卡片 | 4 层；无 bullets；主 CTA ≥44px |
| 最新写作 | 不重复 featured / sync 周报同篇 |

### 1280px（desktop）

| 规则 | 要求 |
| --- | --- |
| 不滚动可见 | Hero +「近期周报」+ ≤1 张完整周报卡 + 另一国 sync row |
| 禁止默认 | 两张完整周报卡并排占首屏 |
| 对照 / Radar | 不与双完整卡叠满首屏；权重低于 featured |
| 卡片 | 同 4 层规则 |

合入门槛：US-1..4 的 AC 全部勾选（US-2.4 可选除外）。US-5..7 不挡 UX PR。

## §5 信息架构（对齐 foundation，桌面收敛）

```
Hero（短）
→ 近期周报
   → Featured 完整卡（4层）     ← 中或日，编辑选
   → Sync compact row           ← 另一国
→ （fold 下）对照句 / Radar / 最新写作 / 三种写作方式 …
```

Mobile 与 Desktop 同一骨架；仅排版宽度不同，不再「桌面双完整卡例外」。
